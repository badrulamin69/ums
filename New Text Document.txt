# Smart University Management System - Angular Frontend Plan

## Backend Summary

**Tech:** Spring Boot 4.0.7 + Spring Security + JWT (JJWT 0.12.6) + JPA + MySQL + Socket.IO  
**API Base:** `http://localhost:8085/api`  
**Response Wrapper:** `ApiResponse<T> { success, message, data, timestamp }`  
**Error Handling:** Global exception handler returns `ApiResponse` with `success: false`

### Roles (from `@PreAuthorize`):
| Role | Access |
|---|---|
| `ADMIN` | Full access to all modules |
| `ADMISSION` | Admission circulars, applicants, merit lists, admit cards, SSC/HSC results |
| `REGISTRAR` | Student management |
| `HR` | Employees, attendance, leave, designations, grades, promotions, separations, appraisals, job postings |
| `PAYROLL` | Payroll runs, salary structures |
| `FACULTY` | Courses, course-teacher assignments, student results, year results |
| `STUDENT` | Default role on registration; owner-based access to own data |

### Permissions: `USER_READ/WRITE/DELETE`, `ROLE_READ/WRITE/DELETE`, `ADMISSION_READ/WRITE/APPROVE`, `ACADEMIC_READ/WRITE`, `STUDENT_READ/WRITE`, `HRM_READ/WRITE/APPROVE`, `PAYROLL_READ/WRITE/APPROVE`, `PAYMENT_READ/WRITE`, `NOTIFICATION_READ/WRITE`, `AUDIT_READ`

### JWT: Access token (15min) + Refresh token (7 days), type claim distinguishes them

## 3. Core Infrastructure

### 3a. `ApiResponse<T>` model
```typescript
export interface ApiResponse<T> {
  success: boolean;
  message: string;
  data: T;
  timestamp: string;
}
```

### 3b. `CryptoService` (CryptoJS)
- Encrypt sensitive payloads (passwords) before sending to backend
- `encrypt(data: string): string` using AES with a frontend key
- `decrypt(data: string): string`
- Used on login/register forms to encrypt password before HTTP transmission

### 3c. `AuthService`
- `login(email, password)` → POST `/api/auth/login`
- `register(email, password)` → POST `/api/auth/register`
- `refreshToken(refreshToken)` → POST `/api/auth/refresh`
- Store tokens: access token in memory, refresh token in `localStorage`
- Decode JWT payload client-side to extract: `email`, `roles[]`, `type`, `userId`, `exp`
- `getLoggedInUser()` → returns decoded token claims
- `hasRole(role: string): boolean`
- `hasPermission(permission: string): boolean`
- `isTokenExpired(): boolean`
- `logout()` → clear tokens, navigate to login

### 3d. Auth Interceptor (`auth.interceptor.ts`)
- HTTP Interceptor that:
  - Attaches `Authorization: Bearer <accessToken>` header to every API request
  - On 401 response: attempts refresh using stored refresh token
  - On refresh failure: logout and redirect to `/login`

### 3e. Error Interceptor (`error.interceptor.ts`)
- Catches HTTP errors
- Maps `ApiResponse` error messages to toast notifications
- Handles 401, 403, 404, 409, 400, 500 status codes with appropriate UI feedback

### 3f. Guards

| Guard | Logic |
|---|---|
| `authGuard` | Check if JWT exists and is not expired → redirect to `/login` if invalid |
| `roleGuard` | Accepts `data: { roles: string[] }` → checks decoded token roles against required |
| `permissionGuard` | Accepts `data: { permissions: string[] }` → checks against token permissions |

Route-level example:
```typescript
{ path: 'admin', canActivate: [authGuard, roleGuard], data: { roles: ['ADMIN'] }, ... }
```

### 3g. `HasRoleDirective` (structural)
- `*hasRole="'ADMIN'"` or `*hasRole="['ADMIN', 'HR']"` — shows/hides DOM elements based on role

## 7. CryptoJS Integration Detail

```typescript
// crypto.service.ts
import * as CryptoJS from 'crypto-js';

@Injectable({ providedIn: 'root' })
export class CryptoService {
  private readonly SECRET_KEY = 'ums-frontend-secret-2026';

  encrypt(data: string): string {
    return CryptoJS.AES.encrypt(data, this.SECRET_KEY).toString();
  }

  decrypt(ciphertext: string): string {
    const bytes = CryptoJS.AES.decrypt(ciphertext, this.SECRET_KEY);
    return bytes.toString(CryptoJS.enc.Utf8);
  }
}
```

**Usage in login:**
```typescript
const encryptedPassword = this.cryptoService.encrypt(this.loginForm.value.password);
this.authService.login(email, encryptedPassword).subscribe(...)
```

## Key Design Decisions

1. **Lazy loading** — Each feature module uses `loadComponent`/`loadChildren` in routes
2. **Bootstrap 5** — No Angular Material conflict; clean, responsive, widely known
3. **JWT decode client-side** — Store in `AuthService`, expose `getRoles()`, `getEmail()`, `getUserId()`
4. **Refresh token in localStorage** — Access token in memory only (lost on refresh, re-fetched)
5. **Owner-based routes** — Backend's `@resourceSecurity.isOwner(#id)` already checks; frontend just needs role guards
6. **All public GETs** (faculties, departments, circulars, document-types, merit-lists) — No auth required; used on landing pages
7. **ApiResponse<T>** — Every service method unwraps `.data` from the response
